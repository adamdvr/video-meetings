# Ralph Loop — правила автономной работы

## Как брать Issues

- Читай title, body и критерий готовности
- Ветку `branch` из `.claude/ralph.config.json` готовит Stop-хук: создаёт её от свежего `main` или переключается на неё. Работай в текущей ветке, не создавай и не переключай ветки сам
- Пропускай Issues с меткой `blocked`: их разбирает человек

## Именование коммитов

- По правилам в skill git-commit

## Правила реализации

- Сначала тесты — потом реализация (TDD)
- После каждого финального изменения запускай тесты
- Если тесты красные после 5 попыток — остановись, напиши в Issue комментарий с описанием проблемы и повесь на неё метку `blocked` (`gh issue edit <номер> --add-label blocked`). Issue не закрывай

## Правила завершения

- Убедись, что все тесты зелёные
- Убедись, что все требования выполнены
- Запусти скилл /code-review для код-ревью
- Запусти скилл /security-review для ревью безопасности
- Закоммить изменения
- Закрой Issue
- Не создавай PR: это сделает Stop-хук
