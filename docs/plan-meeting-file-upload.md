# Plan: Загрузка файлов встречи

**PRD:** [docs/prd-meeting-file-upload.md](prd-meeting-file-upload.md)

**Дата:** 2026-11-06

## Фазы реализации

Фазы идут по порядку: каждая опирается на api или страницу из предыдущих и оставляет приложение рабочим, поэтому остановиться можно после любой.

Каждая фаза начинается с e2e-тестов: в api это Vitest и supertest (`apps/api/test`), в web — Playwright Test, который подключает фаза 2.

1. Написать тесты на критерии фазы до кода.
2. Запустить их и убедиться, что они красные по нужной причине. Ожидаемый 404 проверяется вместе с позитивным сценарием, иначе тест «пройдёт» на 404 от ещё не существующего роута.
3. Реализовать фазу, пока тесты не станут зелёными, и закончить честным прогоном `npm run test:e2e -- --force`.

Вручную остаётся то, что в e2e не автоматизировать: файл в 1 ГБ, память процессов, перезапуск приложений и проверка UI из `apps/web/CLAUDE.md`.

Красные тесты и хуки. Stop-хук прогоняет `test:e2e` api в конце хода и блокирует его, пока тесты красные; web-тесты он не запускает, но `check-types` и `lint` по ним должны проходить. Отключить хук на красную фазу (`.claude/hooks/.verify-off`) — решение пользователя. pre-commit не пропускает красные тесты, поэтому они коммитятся вместе с реализацией.

## Фаза 1: Хранение, загрузка и скачивание в api

**Цель:** минимальный путь файла через api (tracer bullet): принять, сохранить на диске, показать в списке и отдать обратно байт в байт.

**Затрагивает:** backend, database

**Задачи:**

- [ ] Сначала e2e-тесты: загрузка → список → скачивание совпадает байт в байт; название с кириллицей и пробелами; одноимённые файлы отдельными строками, новые сверху; 404 другому пользователю на загрузку, список и скачивание; 401 без токена.
- [ ] Модель файла встречи в Prisma (встреча, исходное название, тип, размер, дата загрузки) и миграция; каталог хранения на локальном диске сервера api, исключённый из git.
- [ ] `POST /meetings/:id/files`: тело пишется на диск потоком, а не целиком в память; запись в БД появляется только после полного приёма файла; чужая или несуществующая встреча — 404, без токена — 401.
- [ ] `GET /meetings/:id/files` (файлы встречи, новые сверху, у каждого название, размер и дата загрузки; одноимённые файлы — отдельные записи) и `GET /meetings/:id/files/:fileId` (файл потоком под исходным названием в `Content-Disposition`, включая кириллицу и пробелы; чужой или несуществующий файл — 404).
- [ ] Документация: `apps/api/CLAUDE.md` (модуль, сообщения, эндпоинты, каталог хранения), README (где лежат файлы, контроль свободного места, файлы от e2e-тестов остаются на диске).

**Когда готова:** e2e-тесты фазы зелёные в `npm run test:e2e -- --force`; файл в 1 ГБ, загруженный в api напрямую через `curl`, скачивается с тем же SHA-256, а память процесса api растёт не более чем на 256 МБ; после перезапуска api файл остаётся в списке и скачивается; `git status` не показывает каталог с файлами.

## Фаза 2: Playwright и страница встречи в web

**Цель:** у web появились e2e-тесты, а пользователь открывает встречу с главной и видит её название, дату и участников.

**Затрагивает:** frontend

**Задачи:**

- [ ] Подключить Playwright Test к web: скрипт `test:e2e` (его запускают `npm run test:e2e` и pre-commit), `webServer` поднимает или переиспользует web и api, артефакты прогона в `.gitignore`.
- [ ] Сначала e2e-тесты: клик по карточке «Последние встречи» и по строке «Все встречи» открывает страницу этой встречи с названием, датой и участниками; без входа — `/login`; чужая и несуществующая встреча — «не найдено».
- [ ] Карточки и строки на главной ведут на страницу встречи; путь страницы добавлен в `matcher` proxy и в саму функцию: без сессии — `/login`.
- [ ] Страница встречи: название, дата и время в часовом поясе браузера (`MeetingDate`), список участников; чужая или несуществующая встреча показывает «не найдено».
- [ ] Документация: README («Тесты», «Git-хук»), корневой `CLAUDE.md` и `apps/web/CLAUDE.md` (в web есть Playwright и что нужно для прогона, страница встречи, правило proxy).

**Когда готова:** e2e-тесты фазы зелёные в `npm run test:e2e -- --force`; проверка UI из `apps/web/CLAUDE.md` (375 px, тёмная тема, клавиатура, axe-core) пройдена; `lint`, `check-types` и `build` зелёные.

## Фаза 3: Список файлов и скачивание в web

**Цель:** на странице встречи есть блок «Файлы» со списком, и файлы скачиваются.

**Затрагивает:** frontend

**Задачи:**

- [ ] Сначала e2e-тесты (файлы кладутся во встречу через api напрямую): список с названием, размером и датой, новые сверху, одноимённые отдельными строками; «Файлов пока нет» во встрече без файлов; «Скачать» отдаёт файл под исходным названием с кириллицей и пробелами и с тем же SHA-256; адрес чужого файла — «не найдено», без входа — `/login`.
- [ ] Блок «Файлы» на странице встречи: список с названием, размером и датой загрузки, новые сверху; состояния «Файлов пока нет», скелетон во время загрузки списка и ошибка с кнопкой «Повторить».
- [ ] «Скачать»: Route Handler web подставляет JWT из cookie и отдаёт файл из api потоком, вне `matcher` proxy и без 10-секундного таймаута `apiFetch`; без сессии — `/login`, чужой или несуществующий файл — «не найдено».
- [ ] Документация: `apps/web/CLAUDE.md` (блок «Файлы», Route Handler скачивания, тип файла зеркалит ответ api), README и корневой `CLAUDE.md` (web → api: файлы идут через Route Handler потоком).

**Когда готова:** e2e-тесты фазы зелёные в `npm run test:e2e -- --force`; файл в 1 ГБ скачивается через web с тем же SHA-256, а память web растёт не более чем на 256 МБ; скелетон и ошибка с «Повторить» проверены вручную на остановленном api; проверка UI из `apps/web/CLAUDE.md` пройдена; `lint`, `check-types` и `build` зелёные.

## Фаза 4: Загрузка файлов в web

**Цель:** пользователь загружает файлы со страницы встречи и сразу видит их в списке.

**Затрагивает:** frontend

**Задачи:**

- [ ] Сначала e2e-тесты: файл загружается кнопкой «Выбрать файлы» и перетаскиванием и появляется в начале списка без перезагрузки; у каждого из нескольких файлов свой прогресс в процентах; SHA-256 скачанного файла совпадает с исходным для 500 КБ, 5 МБ и 50 МБ.
- [ ] Route Handler загрузки: передаёт тело запроса в api потоком с JWT из cookie, вне `matcher` proxy и без таймаута `apiFetch`, поэтому файл до 1 ГБ не обрезается и не копится в памяти.
- [ ] Область загрузки в блоке «Файлы», в том числе во встрече без файлов: кнопка «Выбрать файлы» и перетаскивание, несколько файлов за раз.
- [ ] Каждый файл загружается отдельным запросом, рядом с ним прогресс в процентах; сбой одного файла не останавливает остальные; загруженный файл появляется в начале списка без перезагрузки страницы.
- [ ] Документация: `apps/web/CLAUDE.md` (загрузка идёт мимо Server Actions и proxy и почему), README и корневой `CLAUDE.md`, если меняется описание web → api.

**Когда готова:** e2e-тесты фазы зелёные в `npm run test:e2e -- --force`; файл в 1 ГБ загружается и скачивается через web с тем же SHA-256, а память web и api растёт не более чем на 256 МБ; после перезапуска api и web файлы остаются в списке и скачиваются; проверка UI из `apps/web/CLAUDE.md` пройдена; `lint`, `check-types` и `build` зелёные.

## Фаза 5: Отказы и обрывы загрузки в api

**Цель:** api принимает только допустимые файлы и не оставляет на диске остатков прерванных загрузок.

**Затрагивает:** backend

**Задачи:**

- [ ] Сначала e2e-тесты: отказ 4xx по формату, пустому файлу и размеру (тест на размер не передаёт гигабайт); после обрыва соединения посреди тела файла нет ни в списке, ни в каталоге хранения.
- [ ] Проверка при загрузке: формат из списка PRD (MP4, WebM, MOV, MP3, M4A, WAV, OGG, PDF, DOCX, PPTX, XLSX, TXT, PNG, JPG, WebP, GIF), непустой файл, не больше 1 ГБ; иначе ответ 4xx с причиной.
- [ ] Отклонённая, отменённая или оборванная загрузка удаляет частично записанный файл с диска и не создаёт записи в БД.
- [ ] Документация: `apps/api/CLAUDE.md` (правила проверки и коды ответов).

**Когда готова:** e2e-тесты фазы зелёные в `npm run test:e2e -- --force`; прямой запрос к api с недопустимым форматом, пустым файлом и файлом больше 1 ГБ получает 4xx; после прерванного посреди загрузки `curl` в каталоге хранения не остаётся его остатков.

## Фаза 6: Отказы, отмена и обрыв связи в web

**Цель:** пользователь видит причину отказа, может отменить загрузку и понимает, что она оборвалась.

**Затрагивает:** frontend

**Задачи:**

- [ ] Сначала e2e-тесты: файл недопустимого формата, пустой и больше 1 ГБ (разреженный, без записи гигабайта на диск) отклоняются до начала загрузки с причиной, а соседние из той же выборки загружаются; после «Отмены» файла нет в списке, остальные загрузки завершаются; после обрыва связи у файла ошибка, в списке его нет, повторная загрузка проходит.
- [ ] Проверка до начала загрузки: у файла недопустимого формата, пустого или больше 1 ГБ показана причина отказа, остальные файлы загружаются; правила совпадают с api.
- [ ] «Отмена» у загружающегося файла прерывает запрос вплоть до api (Route Handler передаёт отмену дальше): файл не попадает в список, остальные загрузки продолжаются.
- [ ] Обрыв связи или отказ api: у файла показана ошибка, неполный файл в списке не появляется, файл можно загрузить заново.
- [ ] Документация: `apps/web/CLAUDE.md` (правила проверки зеркалят api, менять вместе).

**Когда готова:** e2e-тесты фазы зелёные в `npm run test:e2e -- --force`; после «Отмены» и обрыва связи в каталоге хранения api не остаётся остатков файла; проверка UI из `apps/web/CLAUDE.md` пройдена; `lint`, `check-types` и `build` зелёные.

## Фаза 7: Просмотр и удаление в api

**Цель:** api отдаёт файлы для просмотра с перемоткой и удаляет их.

**Затрагивает:** backend, database

**Задачи:**

- [ ] Сначала e2e-тесты: просмотр отдаёт файл как `inline` с типом из списка форматов и `nosniff`; Range-запрос получает 206 и нужный диапазон байт; после удаления файла нет ни в списке, ни в каталоге хранения, а скачивание отвечает 404; другой пользователь получает 404 на просмотр и удаление, без токена — 401.
- [ ] Режим просмотра: файл отдаётся для показа в браузере (`Content-Disposition: inline`) с типом по списку допустимых форматов, а не из заголовка клиента, и с `X-Content-Type-Options: nosniff`.
- [ ] Range-запросы при раздаче файла (ответ 206), чтобы видео и аудио перематывались без полной загрузки.
- [ ] `DELETE /meetings/:id/files/:fileId`: файл удаляется из БД и с диска, после этого его адрес отвечает 404.
- [ ] Документация: `apps/api/CLAUDE.md` (просмотр, Range, удаление).

**Когда готова:** e2e-тесты фазы зелёные в `npm run test:e2e -- --force`; `curl` с заголовком `Range` получает 206 и `Content-Range`.

## Фаза 8: Просмотр и удаление в web

**Цель:** пользователь смотрит видео, аудио, PDF и изображения в браузере и удаляет ненужные файлы.

**Затрагивает:** frontend

**Задачи:**

- [ ] Сначала e2e-тесты: «Смотреть» есть у видео, аудио, PDF и изображений и открывает их без скачивания, у DOCX, PPTX, XLSX и TXT этой кнопки нет; видео перематывается в середину до окончания загрузки (запрос с `Range` получает 206); файл, который браузер не воспроизводит, показывает сообщение со «Скачать»; «Удалить» после согласия убирает файл из списка, и его адрес отвечает «не найдено», после отказа файл остаётся. Chromium из Playwright не играет H.264, поэтому воспроизводимое видео в тестах — WebM.
- [ ] «Смотреть» открывает видео, аудио, PDF и изображения в браузере без скачивания; Route Handler просмотра передаёт `Range` в api и отдаёт ответ 206 потоком, поэтому видео и аудио перематываются на любое место.
- [ ] Если браузер не смог открыть файл, показано сообщение с кнопкой «Скачать».
- [ ] «Удалить» с подтверждением: после согласия файл исчезает из списка, после отказа ничего не меняется.
- [ ] Документация: `apps/web/CLAUDE.md` (просмотр, Range, удаление), README при изменении описания web → api.

**Когда готова:** e2e-тесты фазы зелёные в `npm run test:e2e -- --force`; MOV, который браузер не воспроизводит, показывает сообщение со «Скачать»; проверка UI из `apps/web/CLAUDE.md` пройдена; `lint`, `check-types` и `build` зелёные.
