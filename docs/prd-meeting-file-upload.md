# PRD: Загрузка файлов встречи

**Дата**: 2026-11-06
**Статус**: Draft

## Цель

Владелец встречи загружает в неё записи (видео, аудио), документы, презентации и изображения, и всё, что относится к встрече, лежит в одном месте: файлы можно посмотреть в браузере, скачать или удалить. Загруженные файлы хранятся на сервере и остаются основой для их последующей обработки в отдельных фичах.

## Пользовательские сценарии

- Пользователь нажимает на встречу в списке на главной -> открывается страница встречи: название, дата, участники и блок «Файлы».
- Пользователь открывает встречу без файлов -> видит область загрузки и сообщение «Файлов пока нет».
- Пользователь выбирает один или несколько файлов кнопкой «Выбрать файлы» или перетаскивает их в область загрузки -> каждый файл загружается отдельно, рядом с ним виден прогресс в процентах.
- Пользователь нажимает «Отмена» у загружающегося файла -> загрузка прерывается, файл не попадает в список, остальные загрузки продолжаются.
- Пользователь выбирает файл недопустимого формата, пустой или больше 1 ГБ -> у этого файла показана причина отказа, остальные файлы загружаются.
- Пользователь теряет связь во время загрузки -> у файла показана ошибка, неполный файл в списке не появляется; файл можно загрузить заново.
- Пользователь дожидается конца загрузки -> файл появляется в начале списка с названием, размером и датой загрузки.
- Пользователь нажимает «Смотреть» у видео, аудио, PDF или изображения -> файл открывается в браузере без скачивания, видео и аудио можно перематывать.
- Пользователь нажимает «Скачать» -> скачивается оригинальный файл под исходным названием.
- Пользователь нажимает «Удалить» и подтверждает -> файл исчезает из списка и удаляется с сервера; если отказаться в окне подтверждения, ничего не меняется.
- Другой пользователь открывает чужую встречу или файл по адресу -> видит «не найдено»; неавторизованный попадает на страницу входа.

## В скоупе

- Страница встречи в web: название, дата и время (в часовом поясе браузера, как на главной), список участников, блок «Файлы». Переход на неё из карточек «Последние встречи» и строк «Все встречи» на главной.
- Загрузка: кнопка «Выбрать файлы» и перетаскивание в область загрузки; несколько файлов за раз; прогресс в процентах и отмена для каждого файла; сбой одного файла не останавливает остальные.
- Допустимые форматы:
  - видео: MP4, WebM, MOV;
  - аудио: MP3, M4A, WAV, OGG;
  - документы и презентации: PDF, DOCX, PPTX, XLSX, TXT;
  - изображения: PNG, JPG, WebP, GIF.
- Максимальный размер одного файла: 1 ГБ. Пустые файлы не принимаются. Файлы с одинаковыми названиями допускаются и хранятся отдельно.
- Хранение: файлы лежат на локальном диске сервера, привязаны к встрече и переживают перезапуск приложения.
- Список файлов во встрече: название, размер, дата загрузки; новые сверху; состояния «загрузка», «пусто», «ошибка» (с кнопкой «Повторить»).
- Действия с файлом:
  - «Смотреть» в браузере: видео, аудио, PDF, изображения;
  - «Скачать»: любой файл, исходное название сохраняется;
  - «Удалить»: с подтверждением, необратимо, файл удаляется и из списка, и с диска.
- Доступ: все операции только у владельца встречи.

## Не в скоупе

- Обработка файлов: расшифровка, анализ, миниатюры, конвертация, проверка на вирусы. Это отдельные фичи, здесь только хранение.
- Внешние хранилища (S3 и аналоги).
- Доступ участников и других пользователей к файлам, публичные ссылки. Участники встречи — это строки, а не аккаунты.
- Запись звонков внутри сервиса: файлы приносит пользователь.
- Создание, редактирование и удаление встреч в web: кнопка «Создать встречу» остаётся без действия.
- Возобновление прерванной загрузки с места обрыва.
- Лимиты на число файлов и общий объём встречи, квоты на пользователя.
- Просмотр DOCX, PPTX, XLSX и TXT в браузере (только скачивание).
- Переименование файлов, папки, версии, поиск и фильтры, постраничный вывод, массовые действия.

## Технические ограничения

- Файлы хранятся на локальном диске сервера api, без S3. Диск конечный, а лимитов на встречу нет: свободное место нужно контролировать вручную. Каталог с файлами не должен попадать в git.
- Браузер не обращается к api напрямую (CORS выключен): загрузка, просмотр и скачивание идут через сервер web, JWT остаётся в httpOnly-cookie и не попадает в клиентский код.
- Лимиты Next.js 16.4 на тело запроса: Server Actions принимают до 1 МБ по умолчанию, а `proxy` (он есть в проекте) буферизует тело в памяти до 10 МБ и молча обрезает остальное, без ошибки. Файл до 1 ГБ не должен ни отклоняться, ни искажаться по дороге; это проверяется контрольной суммой в критериях ниже.
- Файл до 1 ГБ нельзя целиком держать в памяти: при нескольких одновременных загрузках процесс упадёт от нехватки памяти.
- Просмотр видео и аудио зависит от поддержки формата и кодека браузером (например, MOV воспроизводится не везде). Если браузер не смог открыть файл, пользователю остаётся скачивание.
- Доступ строится на владельце встречи (`ownerId`): как и для самих встреч, чужая или несуществующая запись отвечает 404, чтобы не раскрывать её существование.
- Интерфейс на HeroUI, тексты на русском; проверка по правилам «Verifying UI changes» из `apps/web/CLAUDE.md` (375 px, тёмная тема, состояния, клавиатура, axe-core).

## Критерии готовности

- [ ] Клик по карточке в «Последних встречах» и по строке в «Всех встречах» открывает страницу этой встречи с названием, датой, участниками и блоком «Файлы».
- [ ] Без входа страница встречи ведёт на `/login`; чужая или несуществующая встреча показывает «не найдено».
- [ ] Файл допустимого формата до 1 ГБ загружается и кнопкой, и перетаскиванием и появляется в списке без перезагрузки страницы.
- [ ] Несколько файлов, выбранных за раз, загружаются независимо: у каждого свой прогресс в процентах, ошибка одного не останавливает остальные.
- [ ] «Отмена» прерывает загрузку: файл не появляется в списке, на диске сервера не остаётся его остатков, остальные загрузки идут дальше.
- [ ] Файл недопустимого формата, пустой или больше 1 ГБ отклоняется с сообщением о причине: в интерфейсе до начала загрузки, а прямой запрос к API получает ответ 4xx.
- [ ] После обрыва соединения во время загрузки файла нет в списке, у него показана ошибка, повторная загрузка возможна.
- [ ] SHA-256 скачанного файла совпадает с SHA-256 исходного для файлов 500 КБ, 5 МБ, 50 МБ и 1 ГБ (размеры по обе стороны порогов 1 МБ и 10 МБ из Next.js).
- [ ] Во время загрузки и скачивания файла в 1 ГБ память процессов web и api растёт не более чем на 256 МБ.
- [ ] После перезапуска api и web загруженные файлы остаются в списке и скачиваются; каталог с файлами не виден в `git status`.
- [ ] В списке у каждого файла есть название, размер и дата загрузки, новые файлы сверху, одноимённые файлы показаны отдельными строками.
- [ ] Во встрече без файлов показано «Файлов пока нет», пока список грузится — скелетон, при сбое — ошибка с кнопкой «Повторить».
- [ ] «Смотреть» открывает в браузере видео, аудио, PDF и изображения, а у DOCX, PPTX, XLSX и TXT этой кнопки нет; видео и аудио перематываются на любое место, не дожидаясь полной загрузки; если браузер не смог воспроизвести файл, показано сообщение с кнопкой «Скачать».
- [ ] «Скачать» отдаёт файл под исходным названием, включая кириллицу и пробелы.
- [ ] «Удалить» просит подтверждение; после согласия файл пропадает из списка и с диска, а его адрес отвечает «не найдено»; после отказа файл остаётся.
- [ ] Другой авторизованный пользователь получает 404 на список, просмотр, скачивание и удаление файлов чужой встречи, пользователь без токена получает 401.
- [ ] E2E-тесты api покрывают загрузку, отказы по формату, размеру и пустому файлу, список, скачивание, удаление и 404 для чужой встречи; `npm run test:e2e -- --force` зелёный.
- [ ] Интерфейс прошёл проверку из `apps/web/CLAUDE.md`: 375 px без горизонтальной прокрутки, все состояния, тёмная тема, клавиатура, без новых нарушений axe-core; `lint`, `check-types` и `build` проходят.
- [ ] README и CLAUDE.md обновлены по правилам «Keeping docs current».
