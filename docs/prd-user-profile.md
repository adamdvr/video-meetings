# PRD: Профиль пользователя и его редактирование

**Дата:** 2026-11-11

**Статус:** Draft

## Цель

Пользователь видит свой профиль и может указать имя, загрузить аватар и сменить пароль. Имя и аватар показываются в шапке приложения, и пользователь сразу видит, под каким аккаунтом вошёл. Смена пароля защищает аккаунт: после неё старый пароль и сессии на других устройствах перестают работать.

## Пользовательские сценарии

- Пользователь нажимает на свой аватар или имя в шапке -> открывается страница профиля `/profile`: аватар, имя, email, дата регистрации, кнопка «Редактировать».
- Пользователь без имени открывает профиль -> вместо имени видит «Имя не указано», в шапке показан email.
- Пользователь без аватара открывает любую страницу -> в шапке и в профиле на месте аватара кружок с первой буквой имени (если имени нет, то email).
- Пользователь нажимает «Редактировать» -> открывается `/profile/edit` с блоками «Профиль» (имя, аватар) и «Смена пароля».
- Пользователь вводит имя и нажимает «Сохранить» -> имя сохраняется и сразу появляется в шапке и в профиле.
- Пользователь очищает поле имени и сохраняет -> имя удаляется, в шапке снова показан email.
- Пользователь вводит имя длиннее 100 символов или только из пробелов -> у поля показана ошибка, ничего не сохраняется.
- Пользователь выбирает изображение PNG, JPG или WebP до 5 МБ -> видит превью, после сохранения аватар показан в шапке и в профиле.
- Пользователь выбирает файл другого формата, пустой или больше 5 МБ -> видит причину отказа, текущий аватар не меняется.
- Пользователь нажимает «Удалить аватар» -> аватар удаляется, на его месте снова кружок с буквой.
- Пользователь вводит текущий пароль, новый пароль и его повтор и нажимает «Сменить пароль» -> видит сообщение «Пароль изменён» и остаётся в системе. Вход со старым паролем больше не работает, а сессии на других устройствах завершены: там открывается страница входа.
- Пользователь вводит неверный текущий пароль -> у поля показана ошибка «Неверный пароль», пароль не меняется.
- Пользователь вводит новый пароль короче 8 или длиннее 128 символов, совпадающий с текущим или не совпадающий с повтором -> у соответствующего поля показана ошибка, пароль не меняется.
- Неавторизованный пользователь открывает `/profile` или `/profile/edit` -> попадает на страницу входа.

## В скоупе

- Страница профиля `/profile`: аватар, имя (или «Имя не указано»), email, дата регистрации, кнопка «Редактировать».
- Страница редактирования `/profile/edit` с двумя независимыми формами, у каждой своя кнопка сохранения:
  - «Профиль»: имя и аватар;
  - «Смена пароля»: текущий пароль, новый пароль, повтор нового пароля.
- Имя: необязательное, от 1 до 100 символов после обрезки пробелов по краям; пустое значение означает, что имени нет. Регистрация не меняется.
- Аватар:
  - форматы PNG, JPG (JPEG), WebP; не больше 5 МБ; пустые файлы не принимаются;
  - содержимое файла должно соответствовать его формату;
  - показывается кругом с обрезкой по центру, превью до сохранения;
  - замена и удаление;
  - запасной вариант: кружок с первой буквой имени или email.
- Шапка приложения (главная, страница встречи, страницы профиля): аватар и имя (или email, если имени нет) вместо одного email; клик ведёт на `/profile`. Кнопка «Выйти» остаётся.
- Смена пароля:
  - требует текущий пароль;
  - новый пароль по правилам регистрации (8–128 символов), отличается от текущего, совпадает с повтором;
  - после смены текущая сессия продолжается, все остальные сессии этого пользователя (токены, выданные до смены) перестают приниматься;
  - пароль менять неудобно, поэтому поля поддерживают менеджеры паролей (`current-password`, `new-password`).
- Доступ: профиль, имя, аватар и смена пароля только у самого пользователя; обе страницы закрыты без сессии.

## Не в скоупе

- Смена email.
- Обрезка и масштабирование аватара в редакторе, анимированные аватары (GIF), SVG.
- Показ аватара и имени другим пользователям (участникам встреч).
- Письмо-уведомление о смене пароля: в проекте нет отправки почты.
- Восстановление забытого пароля.
- Ограничение числа попыток ввода текущего пароля (его нет и у входа).
- Список активных сессий и ручное завершение отдельных сессий.
- Удаление аккаунта.
- Поле «Имя» в форме регистрации.

## Технические ограничения

- В модели `User` есть только `email` и хеш пароля, поэтому имя, аватар и признак, отменяющий старые сессии, — новые данные пользователя (миграция БД).
- JWT сейчас без состояния: api проверяет только подпись и срок (7 дней). Чтобы завершать другие сессии после смены пароля, api должен на каждом защищённом запросе сверять токен с текущим состоянием пользователя в БД. Без этого украденный токен проживёт до 7 дней после смены пароля.
- Текущей сессии после смены пароля нужен новый токен в cookie `access_token`, иначе она завершится вместе с остальными.
- Проверка сессии в web оптимистичная (только по cookie, без подписи). Отозванный токен web считает действительным, пока api не ответит 401. На 401 web должен удалять cookie и отправлять на `/login`, как уже делает удаление файла.
- Браузер не обращается к api напрямую: байты аватара при загрузке и показе идут через web (Route Handler). Server Action принимает тело до 1 МБ, а лимит аватара 5 МБ.
- Аватар хранится на локальном диске сервера рядом с файлами встреч (`FILES_DIR`) и переживает перезапуск. Тип файла определяется по таблице форматов сервера, а не по данным клиента, как у файлов встреч.
- В шапке аватар грузится на каждой странице, поэтому показ не должен задерживать отрисовку шапки и списка встреч.
- Новые страницы `/profile` и `/profile/edit` нужно закрыть в proxy (`matcher` и функция), как `/` и `/meetings/:id`.

## Критерии готовности

- [ ] `/profile` показывает аватар (или кружок с буквой), имя (или «Имя не указано»), email и дату регистрации; кнопка «Редактировать» ведёт на `/profile/edit`.
- [ ] Без сессии `/profile` и `/profile/edit` перенаправляют на `/login`.
- [ ] Сохранённое имя видно в шапке на главной, на странице встречи и в профиле без перезахода в аккаунт.
- [ ] Очистка имени возвращает в шапку email; имя из одних пробелов или длиннее 100 символов отклоняется с ошибкой у поля.
- [ ] Загруженный PNG, JPG или WebP до 5 МБ показывается в шапке и в профиле и остаётся после перезапуска api.
- [ ] Файл другого формата, пустой, больше 5 МБ или с содержимым, не соответствующим расширению, отклоняется с понятной причиной, а прежний аватар остаётся.
- [ ] После «Удалить аватар» в шапке и профиле показан кружок с буквой, файл аватара удалён с диска.
- [ ] Аватар одного пользователя нельзя получить, будучи залогиненным другим пользователем или без сессии.
- [ ] Смена пароля с верным текущим паролем: показано «Пароль изменён», пользователь остаётся в системе, вход со старым паролем даёт «Неверный email или пароль», а с новым проходит.
- [ ] Токен, выданный до смены пароля (другая сессия), получает от api 401; в web такая сессия попадает на `/login`.
- [ ] Неверный текущий пароль, новый пароль вне 8–128 символов, совпадающий с текущим или не совпадающий с повтором: ошибка у соответствующего поля, пароль не меняется.
- [ ] Хеш пароля и путь к аватару на диске не попадают ни в один ответ api.
- [ ] Сценарии покрыты e2e-тестами api (Vitest) и web (Playwright), `npx turbo run lint check-types test test:e2e build` зелёный.
